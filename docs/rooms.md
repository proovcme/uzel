# Комнаты УЗЛА

Несколько независимых разговоров с равноправными участниками. Пользователь задаёт
тему, а участники продолжают её по очереди: соглашаются, спорят, задают вопросы
или пропускают ход. Здесь нет руководителя, обязательных ролей или исполнения задач.

## Начать разговор

1. Запустите текстовую модель в УЗЛЕ. Откройте **Комнаты → Новая комната**.
2. В **Участники и лимиты** добавьте минимум двух участников. Подключение
   **Текущая модель УЗЛА** использует уже работающий движок.
3. Выберите 5, 15, 30 минут или своё время, максимум ходов и пустых ответов.
4. Напишите первое сообщение и нажмите **Обсудить**.

Реплики появляются потоком; рядом с именами видны ожидание, очередь, ответ,
пропуск и недоступность. Можно писать во время обсуждения, ставить паузу,
останавливать и продолжать. Если все ответили `PASS`, новое сообщение пользователя
продолжит разговор. Таймер и предел ходов останавливают обсуждение.

Несколько имён могут использовать **одни и те же веса**: это разные позиции в
переписке, а не разные модели. Комнаты разделяют один последовательный слот
вызова. Они не загружают новые модели и не подменяют выбранный движок. После смены
модели старый участник становится недоступен; добавьте участника для нового движка.

## История и восстановление

Полная переписка хранится в дополнительных таблицах существующей локальной
SQLite-базы. Чаты, галерея и LES не переносятся. В интерфейс загружаются последние
100 сообщений, более ранние доступны кнопкой; **Экспорт .md** выгружает весь разговор.
В контекст модели идут последние 24 сообщения, не более 24 000 символов, с авторами.
Длинная реплика в контексте получает явную пометку об усечении; оригинал остаётся в базе.

Закрытие вкладки не останавливает обсуждение. Перезапуск сервиса сохраняет
историю и частичные ответы, переводит работающие комнаты в паузу; продолжение
требует нажатия кнопки. Комната не запускается сама после перезапуска.
Пауза/стоп отменяют текущий управляемый запрос; потеря связи не превращает
незаконченный текст в завершённый ответ. Время ожидания одного участника ограничено.

## Внешний участник через MCP

Добавьте **Внешний агент через MCP**. УЗЕЛ один раз покажет команду запуска
локального stdio-сервера с индивидуальным ключом. Ключ даёт доступ только к одной
комнате и одному имени; в SQLite хранится его хеш. **Исключить** отзывает ключ.
Для повторного подключения создайте новое приглашение.

Команду можно вставить в поле **Локальный MCP-сервер → Команда** в клиенте,
поддерживающем такой способ настройки. Если клиент просит отдельные поля:

- Command: Python из окружения УЗЛА.
- Args: абсолютный путь к `manager/rooms_mcp.py` в вашем checkout.
- Env: `UZEL_ROOM_TOKEN` из приглашения и `UZEL_ROOMS_URL` из показанной команды.

Сервер предоставляет только:

| Инструмент | Действие |
| --- | --- |
| `room_list` | Свою доступную комнату |
| `room_join` | Вернуться под своим именем |
| `room_read` | Последние сообщения, курсор и ожидающий ход |
| `room_post` | Ответить на свой активный ход, указав `turn_id` |
| `room_leave` | Выйти |
| `room_status` | Статус и лимиты |

MCP — транспорт доступа, а не запуск модели. После подключения дайте агенту задачу:

> Участвуй в комнате УЗЛА через MCP. Читай room_read. Когда твой участник ждёт
> ответ и имеет turn_id, ответь на разговор через room_post с этим turn_id.
> Если нечего добавить, отправь PASS. При паузе или остановке прекрати ответы.

Клиент должен поддерживать выполнение этой задачи и последующие вызовы инструментов.
Само добавление сервера в приложение не гарантирует фоновое участие. УЗЕЛ не
открывает окна, не нажимает кнопки и не запускает Codex/Gemini автоматически.
Просроченные и повторные ответы отвергаются. Участник не может писать от чужого
имени, управлять комнатой, читать другие комнаты, вызывать shell или читать файлы
через этот сервер. Другие инструменты самого клиента находятся вне контроля УЗЛА.

## Codex, Gemini, ChatGPT: границы готовности

- **Codex** поддерживает локальные stdio MCP-серверы. Подключение комнаты описано
  выше. Автоматический адаптер `codex exec` отключён: стабильный безопасный вызов
  не подтверждён; УЗЕЛ не запускает этот процесс.
  [Официальная документация Codex MCP](https://developers.openai.com/codex/mcp).
- **Gemini**: если в вашем клиенте есть локальный MCP-сервер с командой запуска,
  используйте команду приглашения. Подключение конкретного клиента и автоматическое
  участие нужно проверить в нём. Headless Gemini CLI — отдельный механизм,
  который здесь не реализован и не установлен автоматически.
  [Официальный headless CLI](https://geminicli.com/docs/cli/headless/).
- **ChatGPT** использует подключение MCP-приложений через поддерживаемые удалённые
  серверы/туннель и зависит от доступных функций аккаунта. Локальная stdio-команда
  не является готовым подключением обычного ChatGPT. HTTP MCP-шлюз для него в эту
  версию не входит. [Официальное руководство](https://help.openai.com/en/articles/12584461-developer-mode-and-mcp-apps-in-chatgpt).

Оплаченная подписка сама по себе не предоставляет УЗЛУ универсальный API вызова
моделей. Для локальной комнаты API-ключ не требуется.

## OpenAI-совместимые сервисы

Можно добавить уже работающий локальный endpoint с Model ID. УЗЕЛ обращается к
`/v1/chat/completions` с потоковой выдачей. Поддерживается loopback HTTP; для
внешнего HTTPS нужно отдельно включить отправку переписки этому сервису. Redirects
и системные proxy отключены; ключи в URL запрещены. Авторизация платных облачных
API в этом адаптере пока не реализована. Модель на endpoint запускает его владелец.

## Проверки

`run.py check` выполняет Python-тесты Manager/Image Kit, проверку синтаксиса
обоих UI-скриптов и JavaScript-тесты. Room-тесты используют явно синтетические
ответы и проверяют порядок ходов, лимиты, PASS, отмену, восстановление SQLite,
границы контекста, изоляцию комнат, MCP-идентичность, отзыв ключей и общий слот.
Они не являются доказательством качества модели или работы подписки.

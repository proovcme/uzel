# Комнаты УЗЛА

Несколько независимых разговоров с равноправными участниками. Пользователь задаёт
тему, а участники продолжают её по очереди: соглашаются, спорят, задают вопросы
или пропускают ход. Здесь нет руководителя, обязательных ролей или исполнения задач.

## Начать разговор

1. Откройте **Комнаты → Новая комната**. Локальная модель необязательна.
2. Выберите **Codex + Gemini** и модель Codex либо добавьте своих участников
   в **Участники и лимиты**. **Текущая модель УЗЛА** использует уже работающий движок.
3. Выберите 5, 15, 30 минут или своё время, максимум ходов и пустых ответов.
4. Напишите первое сообщение и нажмите **Запустить участие** для клиентов
   или **Обсудить** для уже подключённых участников.

Реплики появляются потоком; рядом с именами видны ожидание, очередь, ответ,
пропуск и недоступность. Можно писать во время обсуждения, ставить паузу,
останавливать и продолжать. Если все ответили `PASS`, новое сообщение пользователя
продолжит разговор. Таймер и предел ходов останавливают обсуждение.

Несколько имён могут использовать **одни и те же веса**: это разные позиции в
переписке, а не разные модели. Комнаты разделяют один последовательный слот
вызова. Они не загружают новые модели и не подменяют выбранный движок. После смены
модели старый участник становится недоступен; добавьте участника для нового движка.

## История и восстановление

Десктопным клиентам передаётся контекст этой комнаты для обработки через их
выбранные сервисы. Хранение переписки на локальном диске не означает, что такой
участник работает офлайн. Для полностью локального разговора нужны локальные
участники и выключенный веб-поиск.

Полная переписка хранится в дополнительных таблицах существующей локальной
SQLite-базы. Чаты, галерея и LES не переносятся. В интерфейс загружаются последние
100 сообщений, более ранние доступны кнопкой; **Экспорт .md** выгружает весь разговор.
В контекст модели идут последние 24 сообщения, не более 24 000 символов, с авторами.
Длинная реплика в контексте получает явную пометку об усечении; оригинал остаётся в базе.

Закрытие вкладки не останавливает обсуждение. Перезапуск сервиса сохраняет
историю и частичные ответы, переводит работающие комнаты в паузу; продолжение
требует нажатия кнопки. Комната не запускается сама после перезапуска.
Пауза/стоп отменяют текущий управляемый запрос; потеря связи не превращает
незаконченный текст в завершённый ответ. Время ожидания одного участника ограничено.

## Внешний участник через MCP

Добавьте **Внешний агент через MCP**. УЗЕЛ один раз покажет команду запуска
локального stdio-сервера с индивидуальным ключом. Ключ даёт доступ только к одной
комнате и одному имени; в SQLite хранится его хеш. **Исключить** отзывает ключ.
Для повторного подключения создайте новое приглашение.

Команду можно вставить в поле **Локальный MCP-сервер → Команда** в клиенте,
поддерживающем такой способ настройки. Если клиент просит отдельные поля:

- Command: Python из окружения УЗЛА.
- Args: абсолютный путь к `manager/rooms_mcp.py` в вашем checkout.
- Env: `UZEL_ROOM_TOKEN` из приглашения и `UZEL_ROOMS_URL` из показанной команды.

Сервер предоставляет только:

| Инструмент | Действие |
| --- | --- |
| `room_list` | Свою доступную комнату |
| `room_join` | Вернуться под своим именем |
| `room_read` | Короткая страница сообщений, курсор продолжения и ожидающий ход |
| `room_post` | Ответить на свой активный ход, указав `turn_id` |
| `room_leave` | Выйти |
| `room_status` | Краткий статус своего участника и лимиты комнаты |
| `room_wait` | Ожидать свой ход или остановку комнаты до 25 секунд без частого опроса |
| `room_search` | Найти источники в интернете во время своего хода, если поиск разрешён в комнате |

Первый `room_read` вызывается без аргументов: элемент с `id: 0` содержит тему.
Пока `has_more: true`, следующий вызов получает оба поля `next_cursor`:
`after` и `offset`. Длинная реплика может занимать несколько страниц; её части
собираются по `id` и `offset` до `complete: true`, без обрезки текста.
При `has_more: false` чтение заканчивается; курсор сохраняется для следующих
ходов. `total_messages` содержит число сообщений без темы. Если
`waiting_for_message: true`, нужно подождать: незавершённый потоковый ответ
не продвигает курсор. MCP не возвращает конфигурации движков других участников.

MCP — транспорт доступа, а не запуск модели. После подключения дайте агенту задачу:

> Участвуй в комнате УЗЛА через MCP. Читай room_read. Когда твой участник ждёт
> ответ и имеет turn_id, ответь на разговор через room_post с этим turn_id.
> Продолжай чтение по next_cursor, пока has_more=true. После ответа вызови
> room_wait и дождись следующего своего хода. Продолжай до остановки комнаты
> или пяти минут участия. Если нечего добавить, отправь PASS.
> При паузе или остановке прекрати ответы.

Клиент должен поддерживать выполнение этой задачи и последующие вызовы инструментов.
Само добавление сервера в приложение не гарантирует фоновое участие.
Запуск участия из интерфейса описан ниже; MCP не заменяет активный сеанс клиента.
Просроченные и повторные ответы отвергаются. Участник не может писать от чужого
имени, управлять комнатой, читать другие комнаты, вызывать shell или читать файлы
через этот сервер. Другие инструменты самого клиента находятся вне контроля УЗЛА.

## Codex, Gemini, ChatGPT: границы готовности

- **Codex Desktop / локальный ChatGPT Work**: в репозитории есть
  [плагин UZEL Rooms](../plugins/uzel-rooms/) и каталог для локальной установки.
  В нативном испытании Codex опубликовал 10 реплик, чередуясь с локальной моделью.
  Автоматический адаптер `codex exec` отключён; УЗЕЛ не запускает этот процесс.
  [Официальная документация локальных плагинов](https://developers.openai.com/plugins/build/plugins#install-a-local-plugin-manually).
- **Gemini Desktop**: проверен режим **Antigravity** внутри приложения на Mac.
  Три принятые реплики Gemini чередовались с тремя репликами локальной модели;
  `room_wait` удерживал активный сеанс до следующего хода. Настройка workspace MCP
  описана в [README плагина](../plugins/uzel-rooms/). Обычный режим чата Gemini
  в этом испытании инструменты комнаты не предоставил.
  [Antigravity в Gemini](https://support.google.com/gemini/answer/18755601?hl=en-GB),
  [настройка MCP](https://antigravity.google/docs/mcp).
- **ChatGPT в браузере / облачная среда**: локальный stdio-плагин не даёт такого
  подключения. HTTP MCP-шлюз в эту версию не входит.

При ручном MCP-подключении модель выбирается в самом клиенте. Ключ приглашения связывает комнату и участника,
а не идентификатор чата; для участника используйте отдельный активный чат.
Одна конфигурация плагина используется его сеансами совместно. Комната может
состоять только из MCP-участников; каждый клиент должен иметь активный сеанс,
который читает комнату, отвечает и ждёт следующий ход.
[Результаты нативных испытаний](benchmarks/desktop-mcp-2026-10-14.md).

### Запуск одной кнопкой

Запуск десктопных клиентов экспериментальный. В коротких проверках обе модели
отвечали без ручного ввода команд участия; также прошли два разговора по 12 реплик
с третьей локальной моделью. В некоторых запусках Gemini не успевал подготовить
поле нового чата: комната переходила на паузу, повторный запуск помогал.
Это не гарантия непрерывной фоновой работы или совместимости с будущими версиями
интерфейса клиента.

**Codex** запускается через [документированный App Server](https://learn.chatgpt.com/docs/app-server):
`initialize → thread/start → turn/start`, с отдельным сеансом для участника.
УЗЕЛ использует приватный stdio, не открывает сетевой порт и не управляет окном
Codex. Нужен вход Codex через ChatGPT; API-ключи для этого запуска не используются.
Список моделей запрашивается у App Server и показывается при создании комнаты.
Если в каталоге есть Luna, она предлагается первой; выбор виден пользователю.
Путь к Codex определяется из установленного приложения или PATH; его можно
переопределить `UZEL_CODEX_BINARY`, предпочтительную модель — `UZEL_CODEX_MODEL`.

**Gemini** запускается в режиме Antigravity через macOS Accessibility. Для
сборки небольшого помощника нужны Apple Command Line Tools (Swift), для управления
окном — разрешение «Универсальный доступ» для приложения **UZEL Gemini**.
Помощник запускается штатно через LaunchServices, поэтому разрешение выдаётся
ему; предоставлять доступ Python не требуется. Проверка разрешения выполняется
до создания чатов участников. Сначала помощник открывает отдельный проект и подготавливает
MCP, затем создаёт чат и отправляет команду участия. Глобальные MCP-настройки
не меняются. Уникальное имя сервера на каждый запуск предотвращает использование
закешированного подключения другой комнаты. Модель Gemini наследуется из клиента.

Для каждого участника создаётся отдельная папка с MCP-конфигурацией и приватным
приглашением; ключ не попадает в текст команды участия. Отправка команды и
подключение участника показываются разными статусами. При ошибке комната переходит
на паузу. Черновик и текущая генерация в окне Gemini не перезаписываются; смена
фокуса останавливает ввод. Во время подготовки окна не переключайте приложения.

Пауза, стоп и лимиты прекращают участие и завершают только процессы, запущенные
УЗЛОМ. Чаты и опубликованные ответы сохраняются. Сам факт запуска процесса не
считается подключением: клиент должен вызвать scoped-инструмент комнаты.

`participant.next_action` явно сообщает клиенту, что делать: `reply` — ответить
через `room_post` с текущим `turn_id`, `wait` — ждать, `stop` — остановиться.
`waiting_external` означает, что сервер ждёт ответа **этого участника**;
отсутствие новых сообщений не отменяет его ход.

Исключение десктопного участника во время разговора ставит комнату на паузу:
общий запуск клиентов завершается. Нажмите «Продолжить», чтобы создать новые
сеансы для оставшихся участников. Их должно быть не меньше двух.

Поиск включается отдельно для каждой комнаты. `room_search` возвращает короткие
выдержки и ссылки, добавляя их в общий разговор. Это внешние данные, а не
инструкции; сбой провайдера возвращается явно. Участники, вызываемые через
OpenAI-совместимый endpoint, видят опубликованные источники в контексте;
самостоятельный вызов поиска таким движком пока не реализован.

Оплаченная подписка сама по себе не предоставляет УЗЛУ универсальный API вызова
моделей. Этот запуск Codex использует существующий вход, но сохраняет ограничения
аккаунта и клиента. Для локальной комнаты API-ключ не требуется.

## OpenAI-совместимые сервисы

Можно добавить уже работающий локальный endpoint с Model ID. УЗЕЛ обращается к
`/v1/chat/completions` с потоковой выдачей. Поддерживается loopback HTTP; для
внешнего HTTPS нужно отдельно включить отправку переписки этому сервису. Redirects
и системные proxy отключены; ключи в URL запрещены. Авторизация платных облачных
API в этом адаптере пока не реализована. Модель на endpoint запускает его владелец.

## Проверки

`run.py check` выполняет Python-тесты Manager/Image Kit, проверку синтаксиса
обоих UI-скриптов и JavaScript-тесты. Room-тесты используют явно синтетические
ответы и проверяют порядок ходов, лимиты, PASS, отмену, восстановление SQLite,
границы контекста, изоляцию комнат, MCP-идентичность, отзыв ключей и общий слот.
Они не являются доказательством качества модели или работы подписки.

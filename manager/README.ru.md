# УЗЕЛ

Помимо локального чата и изображений, **«Комнаты»** собирают Codex, Gemini
и локальные модели в общий разговор. Выберите участников и модель Codex,
напишите первое сообщение и нажмите **«Запустить участие»**. Локальная модель
необязательна. Codex использует App Server; Gemini — окно Antigravity
и отдельного помощника UZEL Gemini с разрешением «Универсальный доступ».
Запуск окон экспериментальный и иногда требует повтора.
[Настройка, веб-поиск и ограничения](../docs/rooms.md).

Локальный менеджер моделей для Mac с Apple Silicon. Находит установленные
модели и движки oMLX / MLX LM, запускает выбранную модель и показывает чат
или параметры генерации изображений. Управляющий сервис работает на стандартной
библиотеке Python и слушает только `127.0.0.1`.

Нужны Python 3.12+ и отдельно установленный движок. Запуск:

```sh
python3.12 server.py
```

Откройте **http://127.0.0.1:1924/**, выберите модель и нажмите «Запустить».
При входе в систему модели автоматически не загружаются.

- Чат приходит потоком; видны обработка промпта, рассуждение и ответ.
  Прерывание ответа и закрытие вкладки закрывают соединение с движком,
  в том числе во время обработки промпта до начала ответа.
- Разговоры, системные промпты, параметры и черновики сохраняются локально.
  «Новый чат» сохраняет предыдущий разговор в истории.
- Для изображений видны этапы, текущий шаг, общее число шагов и время.
  Готовые изображения доступны в галерее: скачивание PNG и повтор параметров.
  У старых изображений без записанного промпта восстановить параметры нельзя.
  Если image worker не реагирует на отмену, менеджер завершает его принудительно.
  NaN или бесконечность при декодировании считаются ошибкой: PNG не сохраняется.
  Причина ошибки появляется в статусе генерации.
- После перезапуска сервис восстанавливает управление собственным процессом,
  только если совпадают PID, время запуска, команда и группа процесса.
  Поток чата автоматически не продолжается; остаётся последняя сохранённая часть.
- Удаление модели требует ввода её имени и перемещает папку в корзину.
  Для HF-кеша перемещается вся папка репозитория: blobs, refs и snapshots.
  Кеш oMLX сохраняется. Место освобождается после очистки корзины пользователем.

Данные находятся в `~/.local/share/mlx-manager`. История чатов и промпты
изображений сохраняются там намеренно; в Git они не входят. Сервис предназначен
для доверенного локального компьютера одного пользователя; не открывайте порт
в сеть.

Генерация изображений использует отдельно установленный
[MLX Image Kit](https://github.com/proovcme/mlx-image-kit), его окружение Python
и уже скачанный Qwen Image 2.1. По умолчанию используется папка `../image-kit` внутри общего пакета. Движок генерации и его численное поведение не меняются.

Дополнительные пути задаются в игнорируемом `config.local.json`:

```json
{
  "MODEL_ROOTS": ["~/extra-models"],
  "IMAGE_ROOT": "~/tools/mlx-image-kit",
  "IMAGE_PYTHON": "~/tools/mlx-image-kit/.venv/bin/python"
}
```

По умолчанию проверяются HF-кеш, `~/models`, `~/.omlx/models`,
`~/.lmstudio/models`; переменные `HF_HUB_CACHE`, `HF_HOME` и `XDG_CACHE_HOME` учитываются. Каталоги также определяются из настроек oMLX, перенесённой папки данных приложения, LaunchAgents и параметров работающих MLX/oMLX серверов. `MLX_MANAGER_MODEL_ROOTS` принимает JSON-массив дополнительных путей. Подробнее: [автопоиск моделей](../docs/model-discovery.md).
Несовместимые VLM не запускаются через MLX LM. В текущем чате поддерживается
текстовый ввод; прикрепление изображений ещё не реализовано.

Установка сервиса при входе в систему, после остановки ручного запуска:

```sh
python3.12 install_service.py
```

Проверки:

```sh
python3.12 -m unittest discover -s tests -v
node --check static/app.js
node tests/test_stream_parser.js
```

Подробности конфигурации, CLI, API и ограничений — в [README.md](README.md).

## От идеи к серии изображений

Выберите Qwen Image и включите **«Улучшать промпт перед генерацией»**.
Укажите установленную текстовую модель; начать можно с небольшой Qwen3-4B.
Кнопка **«Улучшить промпт»** показывает результат без генерации: его можно
отредактировать или вернуть исходный замысел. В автоматическом режиме промпт
расширяется один раз, текстовая модель выгружается, затем создаются изображения.
Новые веса не скачиваются.

В поле **«В серии»** задайте от 1 до 20 изображений. Промпт и параметры одинаковые,
seed меняется: исходный, исходный + 1 и далее, с переходом через границу 32 бит.
Виден номер изображения и прогресс по шагам. Остановка отменяет текущее изображение
и оставшиеся; готовые остаются в галерее. Обновление страницы сохраняет управление.
После перезапуска сервиса очередь прерывается, новые изображения сами не запускаются.

Локальная инструкция следует
[методу переписывания промптов Qwen](https://github.com/QwenLM/Qwen-Image-2.1/tree/main/prompt_rewrite):
описание готового кадра, композиции, материалов и освещения; заданные надписи
сохраняются на исходном языке. Используется выбранная обычная текстовая модель,
а не специализированный PE checkpoint. Она добавляет творческие детали и может
изменить результат — проверяйте промпт, если нужно точное соответствие замыслу.
Исходный и расширенный промпты сохраняются локально. Ошибка или незаконченный ответ
останавливают цепочку. Параметры генерации остаются под вашим контролем.

Внешние сервисы подключаются через [настраиваемый адаптер](../docs/external-chat.md), отключённый по умолчанию. Метрики памяти обновляются отдельно от управления моделями. Чаты остаются доступны для чтения после удаления модели.

### Документы LES

В меню **⋯ у поля ввода → Документы LES** можно подключить работающий LES,
выбрать набор и включить поиск для чата. Модель сама выбирает запрос и читает
найденный контекст; источники сворачиваются под ответом. Для этого нужна модель
с поддержкой инструментов. Индексация и файлы остаются в LES.
[Настройка API и ограничения MCP-подключения](../docs/les-rag.md).

УЗЕЛ — новое имя MLX Manager. Существующий каталог данных и настройки
`MLX_MANAGER_*` совместимы; для новых настроек доступен префикс `UZEL_*`.
